# Rename `mise-claude` / `claude-env` → `rytmyk/tune` Design

**Date:** 2026-05-09
**Branch:** new branch off `main` (after PR #1 merges) — proposed `feat/rename-to-tune`
**Scope:** End-to-end rebrand of the project. Org migrates from `komune-io` to `rytmyk`. Cargo crate becomes `rytmyk-tune`, but the user-visible binary, config file, and mise plugin all carry the short name `tune`.

## Background and Goal

Today the project is two artifacts under the same repo:
- A mise Lua backend plugin (root) — bootstraps the Rust binary
- A Rust CLI (`claude-env/`) — declarative Claude tooling manager

The original "claude-env" name no longer fits the trajectory: the tool will become an *agent-agnostic* package manager (Claude Code today; Codex, OpenCode, aider tomorrow). The user wants:

- Music-themed name (org `rytmyk` reads as *rhythmic*)
- Short, agent-neutral, future-proof
- Available on crates.io

The crate `tune` is taken on crates.io by an active microtonal music project (50k downloads, last updated 2024-07). The accepted resolution: publish as `rytmyk-tune` on crates.io, but expose the binary, config, and plugin as `tune`. Cargo supports this via `[lib]` + `[[bin]]` overrides.

## Naming Map

| Field | Today | After rename |
|-------|-------|--------------|
| GitHub repo | `komune-io/mise-claude` | `rytmyk/tune` |
| Cargo crate name | `claude-env` | `rytmyk-tune` |
| Cargo lib name | (default = `claude_env`) | `tune` |
| Binary | `claude-env` | `tune` |
| Subcrate directory | `claude-env/` | `tune/` |
| Project config file | `claude-env.toml` | `tune.toml` |
| Lockfile | `claude-env.lock` | `tune.lock` |
| Cache directory | `~/.claude-env/packages/` | `~/.tune/packages/` |
| Mise plugin name | `claude` | `tune` |
| `.mise.toml` declaration | `claude = "latest"` | `tune = "latest"` |

**No expansion.** The name `tune` stands alone as a music word, in the same lineage as `cargo`, `brew`, `mise`, `bun`. No backronym in any user-facing surface.

**Do NOT rename:**
- `claude-code = "latest"` in samples — that's the Claude Code CLI npm package (the agent itself, third-party)
- `.claude/`, `.mcp.json`, `.claude/settings.json` paths — those are Claude Code's own files; we install into them but don't own them
- `~/.claude.json` reads in `inspect/scanner.rs` — same reason
- The historical `docs/superpowers/specs/` and `docs/superpowers/plans/` — kept verbatim as record of the project at the time those decisions were made

## Architecture

The Cargo trick to get a clean binary name despite a prefixed crate name:

```toml
# tune/Cargo.toml
[package]
name = "rytmyk-tune"
version = "0.1.0"
edition = "2021"
description = "Declarative agent-tool environment manager"
license = "MIT"
repository = "https://github.com/rytmyk/tune"
keywords = ["agent", "claude", "mcp", "ai", "tooling"]
categories = ["command-line-utilities", "development-tools"]

[lib]
name = "tune"            # internal `use tune::...` imports

[[bin]]
name = "tune"            # binary in PATH
path = "src/main.rs"
```

Effects:
- `cargo install rytmyk-tune` installs the package
- The installed binary is `tune` (lands in `~/.cargo/bin/tune`)
- All Rust source uses `use tune::...` rather than `use claude_env::...`
- The `[lib] name = "tune"` ensures both lib and bin share the short identifier internally

## Touch-Point Inventory

### 1. Rust crate (claude-env/ → tune/)

**Directory:** `git mv claude-env tune` — preserves git history.

**`tune/Cargo.toml`:** new package name `rytmyk-tune`, new lib name `tune`, new bin name `tune`, updated description, keywords, repository URL.

**Source files** (string-level rename, hyphens to slashes carefully — `claude-env` → `tune`, `claude_env` → `tune`):

- `src/main.rs` — 38 references including module imports (`use claude_env::...`), default config path `"claude-env.toml"`, default lockfile `"claude-env.lock"`, error messages, exit-on-existing-file checks
- `src/cli.rs` — 11 references: `#[command(name = "claude-env", ...)]`, all doc comments referencing `claude-env.toml`
- `src/config.rs` — 2 doc-comment references
- `src/lockfile.rs` — 2 references including the header string `"# Auto-generated by claude-env. Do not edit.\n\n"`
- `src/migrate.rs` — references `claude-env.toml` as the output filename. Migrate command stays — it migrates `.mise.toml` `claude:*` syntax to the new config (output renamed to `tune.toml`). One-shot helper for users coming from pre-merge layout.
- `src/tui/ui.rs` — references for header text / branding
- All test files in `tests/integration/` and `tests/unit/` — fixtures with `claude-env.toml` paths, expected output strings, assertion text
- `tests/integration/fixtures/full_config.toml` — keep filename, only contents need renaming if they reference `claude-env`

**Cache directory location** in source: `~/.claude-env/packages/` → `~/.tune/packages/`. Find the constant defining this (likely in `src/npm.rs` or wherever the cache root is computed).

### 2. Lua mise plugin (root)

**`hooks/backend_list_versions.lua`:** crates.io URL → `crates/rytmyk-tune/versions`.

**`hooks/backend_exec_env.lua`:**

### 7. crates.io publish

- Verify `rytmyk-tune` is available on crates.io before publishing. (Likely yes; org-prefixed names are usually open.)
- New publish under `rytmyk-tune` v0.1.0 (or v0.2.0 if we want to signal the rename).
- Old `claude-env` crate at v0.1.0 stays published; do not yank — yanking only removes from solver, file remains accessible. No upside to yanking.

### 8. GitHub repo migration

User-driven, performed via GitHub UI:

1. Create `rytmyk` org if it doesn't already exist.
2. Settings on `komune-io/mise-claude` → Transfer ownership → `rytmyk`.
3. Rename within `rytmyk` org → `tune`.
4. GitHub auto-redirects old URLs (`komune-io/mise-claude`) to new URL (`rytmyk/tune`) indefinitely.
5. Reattach CI secrets: `CARGO_REGISTRY_TOKEN`, `CLAUDE_API_KEY`. (May or may not transfer with the repo — check after transfer.)

The code-side updates (Cargo.toml `repository`, README badges, any URL strings in docs) get bundled into the rename PR.

### 9. Backward compatibility

**Hard cutover, no shims.** Project is pre-1.0, no users in the wild. If anyone has a `claude-env.toml` they can `mv claude-env.toml tune.toml`.

The `migrate` subcommand stays useful — it converts pre-merge `.mise.toml` `claude:*` syntax → new config file. Output filename changes from `claude-env.toml` to `tune.toml`. No backward read of `claude-env.toml`.

## Risks

- **`rytmyk-tune` taken on crates.io** — must verify before commit 1. If taken, fall back to `tune-rytmyk` or another prefix.
- **`tune` binary collision on user's PATH** — there's already a `tune` crate (microtonal music). If a user has both installed, the second `cargo install` shadows the first. Acceptable — mise plugin install path is isolated from `~/.cargo/bin` anyway (mise installs to its own shim dir).
- **Lib rename breaks existing `use` paths in tests/external code** — only internal callers (the `tests/` modules and `main.rs`) `use claude_env::`. Switching to `use tune::` is mechanical with sed.
- **Old crate references in docs/superpowers/** — frozen historical record, intentionally not updated. PR description should call this out so reviewers don't flag.
- **GitHub URL redirect lag** — GitHub maintains the redirect "indefinitely" but external bookmarks may take a moment to refresh. Low impact.

## Out of Scope

- Multi-agent support (Codex / OpenCode / aider integration) — separate future work, doesn't affect the rename
- Renaming the `claude-code` mise tool (third-party npm package, not ours)
- Renaming any historical specs/plans
- Yanking the old `claude-env` crate from crates.io
