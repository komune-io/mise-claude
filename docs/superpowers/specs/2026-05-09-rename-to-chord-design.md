# Rename `mise-claude` / `claude-env` → `rytmyk/chord` Design

**Date:** 2026-05-09
**Branch:** new branch off `main` (after PR #1 merges) — proposed `feat/rename-to-chord`
**Scope:** End-to-end rebrand of the project. Org migrates from `komune-io` to `rytmyk`. Cargo crate becomes `rytmyk-chord`, but the user-visible binary, config file, and mise plugin all carry the short name `chord`.

## Background and Goal

Today the project is two artifacts under the same repo:
- A mise Lua backend plugin (root) — bootstraps the Rust binary
- A Rust CLI (`claude-env/`) — declarative Claude tooling manager

The original "claude-env" name no longer fits the trajectory: the tool will become an *agent-agnostic* package manager (Claude Code today; Codex, OpenCode, aider tomorrow). The new identity:

- Music-themed (org `rytmyk` reads as *rhythmic*; `chord` is a fundamental music concept)
- Semantic match: a chord is a collection of notes played together → a `chord.toml` is a collection of agent tools installed together
- Future-proof: a chord is instrument-agnostic — works for any agent

The crate `chord` is taken on crates.io by a wrapper around `d3-chord` — but it is dormant (last update 2021-01-06, only 25 recent downloads). The accepted resolution: publish as `rytmyk-chord` on crates.io, but expose the binary, config, and plugin as `chord`. Cargo supports this via `[lib]` + `[[bin]]` overrides.

## Naming Map

| Field | Today | After rename |
|-------|-------|--------------|
| GitHub repo | `komune-io/mise-claude` | `rytmyk/chord` |
| Cargo crate name | `claude-env` | `rytmyk-chord` |
| Cargo lib name | (default = `claude_env`) | `chord` |
| Binary | `claude-env` | `chord` |
| Subcrate directory | `claude-env/` | `chord/` |
| Project config file | `claude-env.toml` | `chord.toml` |
| Lockfile | `claude-env.lock` | `chord.lock` |
| Cache directory | `~/.claude-env/packages/` | `~/.chord/packages/` |
| Mise plugin name | `claude` | `chord` |
| `.mise.toml` declaration | `claude = "latest"` | `chord = "latest"` |

**No expansion.** The name `chord` stands alone as a music word, in the same lineage as `cargo`, `brew`, `mise`, `bun`. No backronym in any user-facing surface.

**Do NOT rename:**
- `claude-code = "latest"` in samples — that's the Claude Code CLI npm package (the agent itself, third-party)
- `.claude/`, `.mcp.json`, `.claude/settings.json` paths — those are Claude Code's own files; we install into them but don't own them
- `~/.claude.json` reads in `inspect/scanner.rs` — same reason
- The historical `docs/superpowers/specs/` and `docs/superpowers/plans/` files — kept verbatim as record of the project at the time those decisions were made

## Architecture

The Cargo trick to get a clean binary name despite a prefixed crate name:

```toml
# chord/Cargo.toml
[package]
name = "rytmyk-chord"
version = "0.1.0"
edition = "2021"
description = "Declarative agent-tool environment manager"
license = "MIT"
repository = "https://github.com/rytmyk/chord"
keywords = ["agent", "claude", "mcp", "ai", "tooling"]
categories = ["command-line-utilities", "development-tools"]

[lib]
name = "chord"           # internal `use chord::...` imports

[[bin]]
name = "chord"           # binary in PATH
path = "src/main.rs"
```

Effects:
- `cargo install rytmyk-chord` installs the package
- The installed binary is `chord` (lands in `~/.cargo/bin/chord`)
- All Rust source uses `use chord::...` rather than `use claude_env::...`
- The `[lib] name = "chord"` ensures both lib and bin share the short identifier internally

### 8. GitHub repo migration

User-driven, performed via GitHub UI:

1. Create `rytmyk` org if it doesn't already exist.
2. Settings on `komune-io/mise-claude` → Transfer ownership → `rytmyk`.
3. Rename within `rytmyk` org → `chord`.
4. GitHub auto-redirects old URLs (`komune-io/mise-claude`) to new URL (`rytmyk/chord`) indefinitely.
5. Reattach CI secrets: `CARGO_REGISTRY_TOKEN`, `CLAUDE_API_KEY`. (May or may not transfer with the repo — check after transfer.)

The code-side updates (Cargo.toml `repository`, README badges, any URL strings in docs) get bundled into the rename PR.

### 9. Backward compatibility

**Hard cutover, no shims.** Project is pre-1.0, no users in the wild. If anyone has a `claude-env.toml` they can `mv claude-env.toml chord.toml`.

The `migrate` subcommand stays useful — it converts pre-merge `.mise.toml` `claude:*` syntax → new config file. Output filename changes from `claude-env.toml` to `chord.toml`. No backward read of `claude-env.toml`.

## Risks

- **Binary name `chord` collision on user PATH** — the dormant `chord` crate (d3-chord wrapper) is a library, not a binary, so `cargo install chord` would fail with "no binary targets" anyway. No PATH conflict possible.
- **Lib rename breaks existing `use` paths in tests/external code** — only internal callers (the `tests/` modules and `main.rs`) `use claude_env::`. Switching to `use chord::` is mechanical with sed.
- **Old crate references in `docs/superpowers/`** — frozen historical record, intentionally not updated. PR description should call this out so reviewers don't flag.
- **GitHub URL redirect lag** — GitHub maintains the redirect "indefinitely" but external bookmarks may take a moment to refresh. Low impact.
- **Search-engine confusion** — `chord` is heavily searched in music contexts. Documentation should always include a qualifier ("chord — agent package manager") in titles and meta descriptions, and the GitHub repo description should lead with the disambiguation.

## Out of Scope

- Multi-agent support (Codex / OpenCode / aider integration) — separate future work, doesn't affect the rename
- Renaming the `claude-code` mise tool (third-party npm package, not ours)
- Renaming any historical specs/plans
- Yanking the old `claude-env` crate from crates.io
